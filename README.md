# make-knowledge-cards

把一篇文章拆成 5～8 张知识卡片，每张只讲一个知识点，带标题、核心知识、简明解释和例子/自测题。

## 解决什么问题

读完一篇长文，重点散落在段落里，复习时还得重读一遍。这个 Skill 把原文的独立知识点提出来，一张卡一个点，直接可背、可自测；重复表述会被合并，信息不够时不硬凑张数。

## 主要功能

- **输入**：对话里粘贴的正文，或本地 `.md` / `.txt` 文件
- **提取**：按"可独立复习的结论/定义/方法/步骤"切分知识点，合并重复，删掉铺垫和过渡句
- **数量策略**：知识点 5～8 个就一卡一点全出；多于 8 个只留最核心的 8 张；少于 5 个照实输出并说明原因
- **卡片四要素**：标题、核心知识、简明解释、例子或自测题
- **忠实原文**：解释和例子必须能在原文找到依据，不补原文没写的因果、数据、注意事项

不支持（遇到会直接说明，不绕道实现）：网页抓取/URL、PDF、图片、音视频、Anki 导入导出、图形界面、`.docx` 类 Office 文件。

## 安装

Skill 是一个纯文件夹，没有依赖、没有脚本，不需要 pip 安装。

1. 把 `skills/make-knowledge-cards/` 整个目录复制到你所用 Agent 的 skills 目录，例如：
   - 豆包 / 兼容 Agent：`<workspace>/.user_skills/make-knowledge-cards`
   - Claude Code 等：`~/.claude/skills/make-knowledge-cards`
2. 确认目录里有 `SKILL.md` 和 `agents/openai.yaml` 两个文件。
3. 校验结构（可选，用官方校验脚本）：

```bash
python quick_validate.py <skills目录>/make-knowledge-cards
```

脚本来自 skill-creator 官方工具，会检查 frontmatter 的 `name` / `description` 是否符合规范。

## 使用方法

**方式一：直接粘贴文章**

```
用 make-knowledge-cards 把下面这篇文章整理成知识卡片：
<粘贴正文>
```

**方式二：本地文件**

```
把 notes/睡眠与记忆.md 提炼成知识卡片
```

Agent 会读取文件、按规则切分知识点，直接按固定模板输出卡片。

**接入 OpenAI 平台 Agent**：`agents/openai.yaml` 里已写好模型、温度、输入输出约束，`instructions` 指向 `../SKILL.md`，把 SKILL.md 作为 system 指令注入即可，无需另外改写提示词。

### 目录结构

```
skills/make-knowledge-cards/
├── SKILL.md            # 唯一的行为规范：流程、数量策略、四要素、自检清单
└── agents/openai.yaml  # OpenAI 平台 Agent 配置（模型/温度/能力边界）
```

### 输出格式

```text
【知识卡片 1】
标题：<标题>
核心知识：<一句话结论>
简明解释：<2-3 句>
例子/自测：<原文例子，或自测题+参考答案>
```

## 输入输出示例

**输入**（摘要，原文约 400 字）

> 睡眠并不是大脑的关机状态。慢波睡眠阶段，海马体会把白天形成的记忆反复"重放"给大脑皮层，变成长期记忆。快速眼动睡眠（REM）更多与情绪记忆和创造性联想有关，并不负责事实性记忆的巩固。学习后当晚被剥夺睡眠的人，第二天的记忆保持率明显低于正常睡眠者。睡眠纺锤波出现在非快速眼动睡眠第二期，数量越多记忆巩固效果越好。深睡眠阶段会清除 β-淀粉样蛋白等代谢废物。咖啡因和酒精都会压缩慢波睡眠时长，从而削弱记忆巩固。规律运动可以增加慢波睡眠比例。

**输出**

```text
【知识卡片 1】
标题：慢波睡眠重放记忆
核心知识：慢波睡眠阶段，海马体会把白天形成的记忆重放给大脑皮层，使其成为长期记忆。
简明解释：记忆先在别处形成，睡眠中通过反复重放转移到皮层并稳定下来；这一步发生在慢波睡眠，而不是清醒时。
例子/自测：白天学过的东西，在哪类睡眠阶段被"搬"到皮层？

【知识卡片 2】
标题：REM 睡眠不负责事实记忆
核心知识：快速眼动睡眠主要处理情绪记忆和创造性联想，不承担事实性记忆的巩固。
简明解释：两类睡眠分工不同，REM 容易被笼统说成"睡眠帮助记忆"，但事实类记忆的巩固并不靠 REM。
例子/自测：判断：REM 睡眠是事实性记忆巩固的主要阶段。（错）

...（共 7 张）
```

**信息不足时**（原文只有 3 个知识点）：

```text
【知识卡片 1】…【知识卡片 2】…【知识卡片 3】…
说明：原文只有 3 个独立知识点，因此输出 3 张，不补足到 5 张。
```

## 测试情况

用 4 类不同体裁的原文实测，格式与规则检查均通过：

| 原文类型 | 知识点 | 输出 | 验证点 |
| --- | --- | --- | --- |
| 科普说明文（睡眠与记忆） | 7 | 7 张 | 不超上限，一卡一点 |
| 操作教程（Git 撤销的 5 种方法） | 6 | 6 张 | 步骤类不合并、不补原文没有的前提 |
| 议论文（远程办公效率） | 5（含重复论点） | 5 张 | 正反双方重复表述被合并，结论按作者主张表述 |
| 短文本（番茄工作法） | 3 | 3 张 + 说明 | 不硬凑到 5 张 |

首轮测试发现过一次真实缺陷：给 `git commit --amend` 补了原文没写的"会改写他人历史"的后果。已据此在 SKILL.md 的"简明解释"和"禁止事项"里加上"不补充原文没有的注意事项、风险提示、操作前提"。
